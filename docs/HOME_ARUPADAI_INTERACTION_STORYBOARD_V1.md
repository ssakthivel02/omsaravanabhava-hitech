# OmSaravanaBhava Hi-Tech — Home & Arupadai Interaction Storyboard V1

## Purpose

Define the intended flagship interaction rhythm so implementation does not drift into generic card grids or excessive animation.

## A. Home storyboard

### Scene 1 — Sacred opening

Visual:
- deep sanctum field;
- luminous Vel-axis geometry;
- restrained lamp-gold/copper accents;
- Tamil-first title and one clear primary action.

Interaction:
- one-time reveal only;
- no autoplay sound;
- no blocking hero video;
- reduced-motion version appears immediately without lost meaning.

Success:
- within seconds the visitor knows this is OmSaravanaBhava/Murugan;
- primary action is obvious;
- LCP remains lightweight.

### Scene 2 — Six-abode invitation

Transition from Vel axis into a six-stop visual rhythm.

Desktop:
- sculptural/connected horizontal or gently curved progression;
- ordinal 01–06;
- active/focus state reveals short identity/source status.

Mobile:
- vertical connected sequence;
- no carousel dependence;
- one stop at a time is readable without hiding the overall journey.

No map until geography is verified.

### Scene 3 — Sacred works constellation

Do not use identical cards.

Use a deliberate editorial composition for:
- Thiruppugazh;
- prayers/mantras;
- other governed works;
- Murugan names/knowledge.

Each entry exposes availability truth without making pending content look broken.

### Scene 4 — Temple intelligence

Show honest scale + completeness:
- source-linked temple identities;
- Arupadai Veedu distinction;
- current visitor-detail coverage;
- path to directory/search.

Do not advertise raw record count as full encyclopedia completeness.

### Scene 5 — Daily/private practice

A calm local tool:
- today's governed focus where available;
- local counter/saved item;
- explicit privacy/local-only cue;
- no streak pressure.

### Scene 6 — Trust layer

Close the home narrative with confidence rather than disclaimers everywhere:
- Sources;
- Completeness;
- Corrections;
- methodology.

## B. Arupadai Veedu storyboard

### Entry

Heading establishes “Six Sacred Abodes” identity and source-aware context.

Do not lead with technical status tables.

### Six-stop progression

Each stop includes:
- ordinal;
- Tamil/English governed name;
- district/location identity if verified;
- source-state cue;
- one meaningful action to temple detail.

Visual differentiation should come from composition/ordinal geometry, not fabricated temple imagery.

### Detail reveal

On focus/selection:
- short identity context;
- official-source indicator where present;
- current availability/pending summary.

Do not expose long history in an interaction tooltip.

### Motion

Allowed:
- subtle axis/line reveal;
- stop emphasis on focus/hover;
- route transition progressive enhancement.

Forbidden:
- scroll-jacking pilgrimage animation;
- auto-advancing carousel;
- continuous glowing particles;
- parallax that destabilizes Tamil reading;
- motion that implies geography/distances before verification.

### Reduced motion

Show the fully composed six-stop layout immediately.

No function or relationship depends on animation.

## C. Micro-interactions

### Buttons/links
- 120–180ms feedback;
- focus state stronger than hover;
- touch feedback not dependent on pointer hover.

### State disclosure
- 180–260ms;
- no accordion animation that hides content from assistive technology;
- status text remains semantic.

### Reader layers
When future canonical/easy/transliteration/meaning layers switch:
- preserve scroll position where practical;
- never crossfade canonical text into a different layer so users may confuse them;
- label each layer explicitly.

## D. Mobile constraints

At 320/390px:
- first home CTA remains comfortably reachable;
- hero geometry never sits behind critical Tamil text;
- six-abode path does not require horizontal swiping;
- sticky controls remain minimal;
- all primary targets target ~44 CSS px where practical.

## E. Performance constraints

- SVG/CSS geometry preferred;
- no full temple corpus in Home initial chunk;
- no large hero media default;
- no runtime animation library unless measured and justified;
- motion must not delay interaction or LCP.

## F. Acceptance

Home/Arupadai visual acceptance requires:
- unmistakable Murugan identity;
- Tamil readability;
- meaningful narrative progression;
- no generic SaaS/card-dashboard feel;
- full reduced-motion parity;
- 320/390/768/1440/1920 review;
- source truth preserved;
- performance budget preserved.
